0. Overview

The repository runs a complete lakehouse on Docker Compose: MinIO-compatible object storage, a Postgres-backed Lakekeeper REST catalog, Spark for ETL and a Jupyter notebook, Prometheus and Grafana, plus two overlays, one per query engine. Both engines read the same tables, use the same user names and enforce the same authorization model.

ComponentVersion / imageRole
Trinotrinodb/trino:484Primary engine. HTTPS 8443, password auth, file-based rules, resource groups, read-only Iceberg connector.
Kyuubi + Sparkiap/kyuubi:1.12.0-spark-3.5.8 (built)Secondary engine. Thrift 10009, JDBC auth via Postgres, Ranger AuthZ plugin inside each Spark engine.
Spark + Icebergiap/spark:3.5.8-iceberg-1.11.0 (built, Java 17)ETL / seeding / maintenance jobs and JupyterLab.

Ranger Adminpython:3.12-slim running ranger-admin-stub.pyLocal simulation of Ranger Admin's policy endpoints. The plugin is real.
Monitoringprom/prometheus:v3.5.0, grafana/grafana:12.1.0Scrapes Trino, Kyuubi, Lakekeeper, storage. Dashboard "Lakehouse POC".
Toolsiap/tools:local (built)pytest, Trino and Hive clients, htpasswd, openssl. Used by every script.
Memory. Core services need about 1.2 GB, Trino about 1.7 GB, the Kyuubi server 0.5 GB plus roughly 0.75 GB per Spark engine. Give Docker at least 8 GB for one engine path and 11 GB for both. The POC was validated on a 7.5 GiB Docker VM with both paths and three engines running, so it works but has little spare.

1. Setup

1.1 Prerequisites

  • Docker Desktop (or Docker Engine) with Compose v2. On Windows, enable Settings → Resources → WSL integration for your distro, then open a new terminal so your user has the docker group.
  • A bash shell (WSL2 Ubuntu, macOS or Linux). All scripts are run from the repository root.
  • Internet access for the first build: image pulls (about 6 GB) and three jars from Maven Central (verified by SHA-1).

1.2 Configure credentials

cp infrastructure/.env.example infrastructure/.env
Local demo passwords. The file is git-ignored; edit values if you want, never commit it.

Users defined there: admin, etl, analyst1, analyst2, restricted1, bench, plus the Grafana admin and the Jupyter token (lakehouse).

1.3 Build and start the core

scripts/start.sh --engine core
Builds the three images on first run (5 to 15 minutes), generates Trino's bcrypt password file, group file and self-signed certificate, then starts storage, Postgres, catalog, Spark/Jupyter and monitoring.

3. Walkthrough, step by step

The fifteen demonstration steps, in order. Each one names the exact command, what to expect and which components talk to each other.

Step 1. Start the core infrastructure

scripts/start.sh --engine core

Talking: lakekeeper → postgres; catalog-init → lakekeeper management API → storage (bucket validation). Idempotent: re-running reports already bootstrapped and warehouse already exists.

Step 2. Initialize the bucket and the catalog namespace

Done by step 1: minio-init creates bucket lakehouse, catalog-init creates the warehouse with credential vending disabled. Namespaces are created by Spark in step 5. To re-run the bootstrap by hand:

cd infrastructure && docker compose run --rm catalog-init && cd ..
Expected output
warehouse 'lakehouse' already exists: id=01a176b5-b04c-7901-a75e-de86ba412948

Step 3. Confirm the Spark configuration

cd infrastructure && docker compose exec spark bash -c 'env | grep -E "AWS_(ACCESS_KEY_ID|REGION)"; spark-sql -e "SHOW NAMESPACES IN lakehouse" 2>/dev/null' && cd ..

Expected: AWS_ACCESS_KEY_ID=..., AWS_REGION=local-01, then the namespace list. The catalog and S3 settings live in infrastructure/spark/spark-defaults.conf; the keys come from the container environment, never from the file.

Steps 4 and 5. Generate data, write bronze, merge silver (CDC), build gold, verify catalog metadata

scripts/seed.sh
About 2 to 3 minutes. Drops and recreates the tables (--reset), generates deterministic bronze data, runs the silver MERGE (dedup + CDC) and rebuilds the gold marts, then prints the catalog state. Use --no-reset to keep tables.

The first connection of a group takes 15 to 40 s while its engine starts. The two xfails are the documented metadata-table gap.

Step 8. Apply analyst roles and workload policies

Policies are files and hot-reload. Trino: infrastructure/trino/rules.json and resource-groups.json (10 s refresh for rules, passwords and groups). Kyuubi: edit infrastructure/kyuubi/authz/policies.json and bump policyVersion; engines poll every 30 s. Server settings in kyuubi-defaults.conf need a restart of the kyuubi service.

cd ..
Expected output

Step 9. Connect as an analyst

Trino, from the tools container (or any JDBC client with the URL in section 2):

cd infrastructure
docker compose run --rm tools python -c "
import os, trino
from trino.auth import BasicAuthentication
c = trino.dbapi.connect(host='trino', port=8443, user='analyst1', auth=BasicAuthentication('analyst1', os.environ['ANALYST_PASSWORD']), http_scheme='https', verify=False, catalog='lakehouse').cursor()
c.execute('SELECT region, SUM(revenue) FROM lakehouse.gold.daily_sales_by_store GROUP BY region ORDER BY 1'); print(c.fetchall())"
cd ..

Kyuubi, with Beeline inside the container:

cd infrastructure
dc exec kyuubi kyuubi-beeline -u "jdbc:hive2://localhost:10009/gold" -n analyst1 -p analyst-pass \
  -e "SELECT region, SUM(revenue) FROM lakehouse.gold.daily_sales_by_store GROUP BY region ORDER BY 1"
cd ..

Both return the same five regions and sums. On Kyuubi, SET spark.app.id returns the same application id for analyst1 and analyst2: a shared engine, not a private Spark application.

Step 11. Show the restricted role being denied or masked

cd infrastructure && docker compose run --rm -e ENGINE=both tools pytest -q -k "pii or masked or street_address or bronze" tests && cd ..

By hand: run q9 as admin (raw values), restricted1 (masked e-mail, phone, national id, year-only birth date, opted-in rows only) and analyst1 (Access Denied on Trino; Permission denied: user [analyst1] does not have [select] privilege on [silver/customer_pii/email] on Kyuubi).

Changing policies

  1. Trino access rules: edit infrastructure/trino/rules.json; reloaded within 10 s; errors appear in dc logs trino (an unknown field aborts the reload, the previous rules stay active).
  2. Trino users / groups: edit .env and run scripts/start.sh --engine trino --no-build to regenerate trino/generated/. Kyuubi users: the Postgres table kyuubi_auth.auth_users is created on first start only; to change a password run dc exec postgres psql -U postgres -d kyuubi_auth and update password_hash = encode(sha256(convert_to('new','UTF8')),'hex').
  3. Kyuubi / Ranger policies: edit infrastructure/kyuubi/authz/policies.json, increase policyVersion, wait 30 s (engine poll). Row filters that must survive constant folding use key < 0 AND key > 0, never 1 = 0.
  4. Groups: both trino/generated/groups.txt (from scripts/_lib.sh) and infrastructure/hadoop/core-site.xml must agree; restart kyuubi after changing the Hadoop mapping.
  5. Kyuubi server settings (share levels, pools, timeouts, queues, restricted confs): kyuubi-defaults.conf, then dc restart kyuubi.
  6. Trino resource groups: resource-groups.json; a restart of trino is the safe way to apply.

Adding a table

Add DDL to spark/create_tables.py (Spark owns metadata), its generator or merge step, a grant in rules.json and in policies.json, a validation query, and an entry in tests/expected.json after one real run. Both engines see it immediately after the Spark commit.

Recovery scenarios

ScenarioSymptomAction
Catalog downBoth engines: table not found / connection refused to lakekeeper:8181dc up -d lakekeeper; Postgres holds state, nothing is lost. Running queries finish.
Storage downReads fail on both engines, ETL failsdc up -d minio; retry. Data is in the volume iap_miniodata.
Trino coordinator down8443 refuseddc up -d trino; stateless; 30 s to healthy.
Kyuubi server down10009 refuseddc up -d kyuubi; engines are relaunched on demand.
Engine OOM / stuckOne group's queries fail or hangdc restart kyuubi (kills all engines) or kill the one engine process inside the container; lower spark.driver.maxResultSize / row caps if it recurs.
Runaway queryHigh latency for everyoneTrino: kill from the Web UI (admin); Kyuubi: close the operation from the UI/REST or wait for kyuubi.operation.query.timeout (15 min).
